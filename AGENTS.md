# Инструкция для агентов (нейросетей)

Проект: `mind_at_play`, Rails 8.1, Ruby 3.4.4, PostgreSQL. Документация и план на русском, комментарии в коде на английском. План: `docs/superpowers/plans/2026-11-22-mind-at-play-mvp.md`, журнал: `docs/superpowers/plans/work_log.md`.

## Как запускать тесты

Замеры на этой машине (8 ядер): весь `bin/rails test` около 27 с, `bin/rubocop` около 8 с, один тестовый файл около 15-20 с. Один вызов инструмента обрывается по таймауту через 30 с. Команда, которую оборвали, не даёт результата, и её приходится запускать заново. Поэтому:

1. **Полный прогон запускайте в фоне с логом, потом читайте лог.** Не запускайте `bin/rails test` напрямую одним вызовом, он близок к лимиту.

   ```
   cd /home/denio/my_prj/self_test/nback && (bin/rails test > /tmp/nback_test.log 2>&1; echo done >> /tmp/nback_test.log) &
   ```

   Затем отдельным вызовом `sleep 25; tail -15 /tmp/nback_test.log`. Готово, когда последняя строка `done`. Итог в строке `N runs, N assertions, 0 failures, 0 errors`. Если `done` ещё нет, повторите только чтение лога, тесты заново не запускайте.
2. **Rubocop** укладывается в лимит, но запускайте его по изменённым путям: `bin/rubocop app config test`. Либо вместе с тестами в фоне, в один лог.
3. **Один файл или один тест** запускается напрямую, с `timeout 28`: `timeout 28 bin/rails test test/controllers/admin/feedback_messages_controller_test.rb`. Один тест: добавьте `:<строка>` (например `test/models/user_test.rb:42`). Для чтения результата достаточно `| tail -15` или `| grep -E 'runs|Failure|Error'`.
4. **Не гоняйте полный набор после каждой правки.** Порядок работы: тест новой задачи (красный) -> код (зелёный) -> файлы рядом с изменением -> один полный прогон в фоне перед коммитом.
5. **Не запускайте два прогона одновременно.** Тесты параллельны (`parallelize(workers: :number_of_processors)`), они создают базы `mind_at_play_test_0 ... _7`. Два прогона одновременно мешают друг другу.
6. **Читайте только хвост вывода.** Полный вывод длинный. При падении ищите `Failure:` или `Error:` и три строки после.
7. Тесты в `test/system` и `node --test test/javascript/` не входят в `bin/rails test`. JS проверяется отдельно: `node --test test/javascript/`, он быстрый.

Если тест красный, а вы его не меняли, остановитесь и не чините чужое (правило плана).

## Правила коммитов

- Коммит по путям (`git add <путь>`), не `git add -A`. Список путей указан в каждой задаче плана.
- После готового коммита добавьте строку в `docs/superpowers/plans/work_log.md` в формате `- <дата время> <номер задачи>: <одно предложение>. Коммит '<сообщение>'.` Время берите из `date '+%Y-%m-%d %H:%M'`. Строка попадает в следующий коммит.
- Перед каждой задачей прочитайте её текст в плане и работайте по TDD: сначала падающий тест, затем код.
- Этапы плана запускаются по одному, начало нового этапа согласуется с владельцем.
